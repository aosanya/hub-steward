# Modules moved to sibling repositories

Each module listed here no longer lives in `code/wakala-api/modules/`. The hub imports it from its sibling repository at a tag, with no `replace` line, and the in-tree folder is deleted. The hub keeps only the wiring around it (route mounts, permission checks, per-agency managers, MCP tool registration). Fixes to a module are made in the sibling, and the hub takes them by moving the tag.

Each sibling lists every difference from the hub copy it replaced, and what the merge took, in its own `documentation/3. implementation/hub-import-drift.md`.

## What to do when a sibling needs a change

Change the sibling, tag it, and raise the version in `code/wakala-api/go.mod` with `go get github.com/aosanya/mwanachama-backend-<name>@<tag>`. Never edit a module in the hub, and never add a `replace` line to a committed `go.mod`.

## Shared version

The siblings require `mwanachama-backend-shared` v0.3.0. The hub requires v0.3.1, which the module graph selects, so the siblings and the hub's other imports read one copy of shared.

## Open after the comm switch

The sibling's tool `comm_chat_thread_read` runs the action `comm.chat_thread.read`. The permission catalogue does not name that action, so only an agency's owner may call it: a member or role holder is refused until the catalogue lists it, for example under `chat.thread`, and a resident is refused until `residentCommActions` in `internal/api/http/resident_comm.go` lists it. The catalogue belongs to the agency sibling. Whether a member or a resident may read a thread by id is the owner's decision; nothing was added in the hub.

## Open in the siblings

- `mwanachama-backend-permissions`: two tests in `routes/`, `TestAQuestionNamingNoScopeIsRefusedEvenForAnEverywhereGrant` and `TestAnEmptySubjectCanNeitherHoldAGrantNorPassTheCheck`, expect `200` for a missing `scope` or `subject` and get `400`, because shared's dispatch now refuses a missing required query argument. The hub does not run them.
- `mwanachama-backend-voting`: two tests in `result_cover_test.go` fail on the tag, `TestPublishingAgainReplacesThePublisherAndGroups` and `TestAPublishedCountIsReadOnlyByAMemberOfAPublishedGroup`. The code is unchanged from the hub; the tests disagree with it. The hub does not run them.
