Run the agency

The agency manager knows who is in the agency and what it is for.

1. Sees who is in the agency

Users lists everyone in the hub as a table with their role, access and when they joined, with a search box, a role filter and one button, Invite a user. The invitation names the person by member code and shows their screen name before it is proposed for approval. Asking "Who joined this week?" fills the content area with only those users.

Open the mockup

2. Sees the groups

Groups lists each group with its number of members, its join mode (open or approval required) and the AI role that speaks there. Opening a group shows its members, and its join mode can be changed from there.

Open the mockup

3. Sees the agency's agents

Agents lists each agent with the model it uses and its state. A Configure link opens the agent's edit page with its model and limits, as in AI roles.

Open the mockup

4. Sees the agency's goals

Goals lists the agency's goals with the number of objectives under each. Opening a goal shows its objectives, the measure of each and the workflows that serve it. Opening an objective shows those workflows and their steps, with the roles on each step. A step's roles appear in a small table where Responsible, Accountable, Consulted or Informed can be ticked; a role may hold two. Approved changes wait in the agency's draft, which is not live: agents and members keep using the published version until the manager publishes.

Open the mockup

5. Sees the agency's roles and publishes

Roles lists the agency's roles, human and AI, each with its description under its name. Opening a role shows what it may do and its members, and its Edit button opens a form that proposes the change for approval. Publish, under Agency in the menu, lists the draft's changes one per line, with the kind, the title, who approved it and when. Publish checks the agency first. If the check finds problems nothing is published: the page lists each as a plain sentence with a link to the page and item to fix, and the button reads Publish again. When the check passes the page shows a quiet line such as "Published as version 4" with the time.

Open the mockup

6. Changes the agency's name and purpose

Profile shows the agency's name, its purpose and its id. A Rename the hub button opens a form, and the change arrives as one card to approve in the chat. An approved rename joins the draft as one more change on the Publish page, and the hub keeps its published name until the manager publishes.

Open the mockup

7. Changes how people join, the language and the theme

General holds Joining (Open to join or Approval required), the default language and the theme: Dark, Light, Midnight, Forest or High contrast. A change to Joining or to the default language waits for the manager's approval before anything is recorded. The theme is kept in the browser, so it is the manager's own on that device and not a setting of the hub.

8. Reads the agency's documents

Documents lists the lab's documents with the languages each exists in, the number of passages and when it was updated, with a search box, a language filter and one button, Upload a document.
