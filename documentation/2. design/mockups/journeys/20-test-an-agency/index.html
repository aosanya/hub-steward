Test an agency

The designer proves the agency's rules work by running scenarios against a test copy, before publishing.

1. Opens Test

Test lists the agency's scenarios as cards, each with a tick box, its result, an Actions menu, what it tries, when it last ran and the tokens it used. One primary button, Run all scenarios, is at the top. With no scenario yet, one card says so and carries Add a scenario.

Open the mockup

2. Runs the scenarios

Ticking rows turns the button into Run 2 selected; the Actions menu holds Run, Open last run, Print report, Edit and Remove for one scenario. After Run all scenarios, as many run at once as the hub's Scenarios at once setting allows and the others wait as Not run yet; each row shows its tokens so far and then its result. Publish stays available and warns about any scenario that has not passed.

Open the mockup

3. Watches a run

A run opens at once and fills step by step with the result Running. The Test agent plays the people in the script and the agency's agents respond, each through the endpoint its module uses in a live run. Under each step the page shows the endpoint it called, what was sent, what the module answered word for word, the new lines it wrote to the trail and the rows it wrote, with the step's tokens; the page ends with what was stored in the test copy. After the run, a Data trail tab lists every line the run wrote, oldest first, each with its step, module and endpoint, and the rows each module's test copy holds at the end. Closing the page does not stop the run.

Open the mockup

4. Reads a failed run

The page stops at the step that went wrong: it shows what was expected and what was found, with the endpoint it called, what was sent and, when the module refused the call, the endpoint's own refusal word for word, and its rule chip says the rule failed, with Open the rule, Run again and Why did this fail? Asking why lands an answer in the content area with the step, the rule, what was expected and found, and the likely cause, linked to the rule and the workflow.

Open the mockup

5. Gives a stopped run more tokens

A run that reached its token budget is Stopped with Budget reached; the steps done so far are kept and Publish warns about it like any scenario that has not passed. Asking for more tokens per test puts the limits form in the content area, the approval stays in the chat, and once approved the card offers Run this scenario again.

Open the mockup

6. Prints a report or opens an earlier run

Once a run has ended, one primary button prints its report: the run's details, the script and who played whom, what transpired, what was stored, the rules held and the draft version with the date and time. An earlier run opens from the scenario's Runs list in the same view, marked with the draft it ran on.

Open the mockup

7. Adds a scenario

Add a scenario opens a form with three tabs. Scenario holds the name and the workflow it follows; Actors holds the people the Test agent plays, one for each role of the workflow, and a second farmer can be added, with names that must differ; Blocks holds the workflow's steps, each with its actor and what goes in, free for the Test agent unless a value is typed. The chat can fill the form too. After Save the scenario is the last row, Not run yet.

Open the mockup

8. Opens, edits or removes a scenario

A scenario opens from its name with its Scenario, Actors and Blocks tabs, read only. Edit has the same three tabs filled in; saving sends the scenario back to Not run yet and its old run stays in its Runs. Remove takes it out of the list. A role or workflow a scenario uses cannot be removed from the agency.

Open the mockup

9. Asks which rules held

Failed only beside Add a scenario shows just the scenarios whose last run failed. Asking which rules held lands each of the agency's rules in the content area: Held where a scenario run shows it, Failed where one broke it and Not tested yet otherwise.

Open the mockup

10. Publishes, warned about any scenario that has not passed

Publish, on its own page, lists what would be published and, under it, each scenario that has not passed on this draft, with its last result and a link to its run. The warning never blocks: Publish stays available and no sign-off is recorded. When every scenario has passed on the draft no warning shows, and one line says a publish reaches members within 30 seconds.
